# Screen design: units of kind screen

| Path | Template | Required |
| --- | --- | --- |
| overview.md | overview.md | yes |
| layout.md | layout.md | yes |
| events.md | events.md | yes |
| data.md | data.md | no |

## Instructions

Describe the screen by what is on it and what happens when the user acts, before the rules behind it. List the items in reading order, the events in the order a user meets them, and the text of every message exactly as it is shown. Cite a business rule from the event or validation that applies it, and name the legacy screen map or program only in the overview, never in the design items. A screen that reads or writes data has `data.md`; a pure menu does not.
