# Changelog

This changelog records the Kintsugi adaptation; it is not tied to a plugin manifest or a marketplace version.

## Unreleased — Kintsugi adaptation

- Codex and GitHub Copilot ([ADR-0072](../../../docs/decisions/0072-init-install-and-plugins-as-plugins.md)). The command `build` of `modernize` is delivered as a skill to the clients that have no commands to run by name (Codex, Copilot) and as the command to Claude Code; the hook it declares is generated as a plugin-wide hook for them and reads their transcripts.

- Login, init, install ([ADR-0072](../../../docs/decisions/0072-init-install-and-plugins-as-plugins.md)). The member plugin `context` is removed: the built-in plugins are `reverse_engineering` (runtime) and `modernize` (both). `modernize` 3.1.0: the command `build` declares the one hook a distributed plugin may carry, `kintsugi activity hook stop --plugin modernize --command build`, which reports who ran it, the tokens, turns and time to the project's monitoring; each member plugin is installed as a plugin of its own, so the command is `/modernize:build`.

- Members build, the runtime reviews ([ADR-0071](../../../docs/decisions/0071-members-build-runtime-reviews.md)). `modernize` 3.0.0 has the audience `both`: the runtime does `design` and the new `review` (the command `modernize-review`, the agent `code-reviewer`, the skill `code-review` and the scripts `prepare_review.py`, `mr_changes.py`, `check_code_review.py` and `render_review.py`: an independent reviewer reads the merge request a member opened, at the head commit the member recorded, and the findings are published as `_build/review.md` per unit), and a member runs the command `build` (`/kintsugi:build <module>/<unit>`, with the skills `build-method` and `unit-testing`) to implement and test a designed unit on their own machine and record which unit was built in which merge request (`activity_record`, kinds `build.test` and `build.mr`). `paths.py` (the same in both plugins) gains the review paths. A plugin of `both` sends a member only its member commands and agents and the skills they name (`BuiltinPlugin.memberFiles`). The proof that a merged unit builds and passes from clean (`verify`) is left for later.

- The Coding Agent Workflow is removed ([ADR-0067](../../../docs/decisions/0067-remove-access-and-review-plugins.md)): the `access` and `review` plugins, the `gate-reviewer` agent, `@kintsugi/agents/access-plugin` and `parseUnitDocument`; the task, review and gate code of the API, portal and orchestrator. The CLI, the client, the SDK, the harness hub and the member token and OAuth connection modules stay as the common member base ([ADR-0069](../../../docs/decisions/0069-common-member-base-and-plugin-distribution.md)). The `design` plugin is merged into `modernize` ([ADR-0068](../../../docs/decisions/0068-design-generation-in-the-modernize-plugin.md)): `modernize` 2.0.0 is a runtime plugin carrying the `design` command, `designer`, `design-reviewer` and `architecture-critic`, the design-set scripts and skills; the commands and agents that only a member's harness ran (`design-architecture`, `scaffold`, `implement`, `scaffolder`, `test-engineer`, the `scaffold` workflow) are gone. The built-in plugins are `reverse_engineering` and `modernize` (runtime) and `context` (member, [ADR-0069](../../../docs/decisions/0069-common-member-base-and-plugin-distribution.md)): a skill that grounds a member's own AI client in the project's document repository and records what was done.

- `inventory.py` reads every kind of file without stopping the stage. EBCDIC text (mainframe sources and data sets, with or without NUL bytes in binary fields) is decoded as cp037; UTF-16 with a byte order mark is decoded; a binary file with a source extension, a source file over `MAX_FILE_BYTES`, and a `.ctl` that is not Visual Basic are counted as `Other` (with a sha256 when read) instead of failing the run; a `.prc` that starts with `//` is JCL. `scripts/languages.py` (about 1,150 extensions and 185 file names, 630 languages) is now generated from Pygments plus the `programming` languages of GitHub Linguist (pinned commit, `gen_languages.py --linguist` for a local copy) and curated z/OS choices: `.ps` (a PS data set, not PostScript), `.csd`, `.dcl` (COBOL), `.mac`, `.dbd`, `.psb` (Assembly), `.proc`, `.cntl`, `.job` (JCL), `.pco`, `.sqb`, `.cb2` (COBOL), `.ezt`.

- Item kinds ([ADR-0060](../../../docs/decisions/0060-item-kinds-and-kind-aware-understanding.md)). `reverse_engineering`: the core kinds and the mapping of topology leaf kinds onto them (`topology_units.py`), specification profiles by kind (`skills/understand-planning/references/spec-profiles/`, `spec_profiles.py`, resolved by `scope_items.py` and checked by `finish_items.py`), the kind mix of each planned batch and a planning rule for entry kinds, and the generated read/write matrix `_generated/DATA_ACCESS.md`.

- A referee or judge that returns no verdict (usually a `result.json` of the wrong shape) gets one more try while the agent cap has room, in `workflows/extract-rules.js` (citation referees) and `workflows/harden-scan.js` (refuters and confirmers). What still has no verdict stays in `unverified`.

- Evidence marks and gaps ([ADR-0057](../../../docs/decisions/0057-evidence-marks-and-gaps.md)). New shared skill `evidence-marks` (`reverse_engineering` 1.1.0): every statement about the legacy system is confirmed (cited), inferred or a gap, and a specification ends with a `Gaps and questions` table (`GAP-<module>.<unit>-NN`; kinds `missing-source`, `unresolved`, `ambiguous`, `unverified`; impact `blocking`, `risk`, `note`) that replaces "Open questions". `legacy-analyst` and `business-rules-extractor` (1.2.0) load it; `finish_items.py` derives `openQuestions` from the table and reports a table that does not read. The `design` plugin (1.2.0) gains the skills `design-template-contract` and `design-writing`; `designer` (2.1.0) is split along them and carries every blocking gap as an open question with an assumption, and `design-reviewer` (1.1.0) reports a blocking gap decided silently as a `major` `clarity` finding. `rebuild_aggregates.py` writes `_generated/GAPS.md` from the units' tables; new `scripts/gaps_common.py` (shared parser) and reader `hooks/reader/gaps.ts` (`parseSpecGaps`, `parseGaps`, `countGaps`), held to the fixture `scripts/tests/fixtures/gaps/spec.md`.

- The agents read the job workspace from its root ([ADR-0055](../../../docs/decisions/0055-one-durable-workspace-per-job.md)): the legacy code is under `as-is/<repository id>/` (it was `src/`), the target code is readable under `to-be/<repository id>/`, and the kernel tells each agent to read `WORKSPACE.md` first. The prompts of the `understand`, `assess` and `design` content (`extract-rules`, `harden-scan` and `portfolio-assess` workflows, the stage commands, `designer`) name `as-is/`; citations are unchanged (`<repository id>/<path>`), and `Owners.path_of` accepts a leading `as-is/` where it accepted `src/`.

- `inventory.py` names the language of a file from a generated table instead of a short hand-written one: `scripts/languages.py` (about 650 extensions and 40 file names, 390 languages: programming, scripting, query, hardware, template and mainframe/4GL languages) is generated by `scripts/gen_languages.py` from the Pygments catalogue plus curated choices (the names the inventory always used, the extensions several languages claim, `.vue`, `.jsp`, `.rpgle`, `.dfm`, PL/SQL, PL/I, Natural and others); data, configuration, log and documentation formats stay "Other", and so does any extension not in the table. A Vue and Java repository now lists both (before, `.vue` was "Other" and left out of every figure). Decision words and comment starts are per language where they differ from the C-family default (Pascal, Lisp, Haskell and ML, Erlang, Perl, shells, Fortran, Ada, PL/SQL, RPG, batch, templates), so SLOC and the complexity proxy are measured the same way for them. Build output folders of the web and JVM toolchains (`.nuxt`, `.next`, `.output`, `.svelte-kit`, `.gradle`, `.turbo`, `.cache`, `bower_components`) are skipped.

- A design run is reviewed by an independent agent ([ADR-0054](../../../docs/decisions/0054-design-run-reviewer-and-pull-request-description.md)). The `design` plugin (1.1.0) gains the runtime agent `design-reviewer` and the scripts `check_review.py` (reads each unit's review note into a report; a note that does not parse counts as not reviewed) and `render_design_review.py` (the state of each unit, ready, ready-with-findings or incomplete, and the open findings). The `design` stage runs a reviewer per unit between the check and the fix round, sends blockers and majors to the fix round with the check problems, and renders the review as the description of the pull request (`StagePlan.description`, `DocumentWriteRequest.description`); the notes stay in scratch. A run takes at most `maxAgents/3` units. `paths.py` gains `design_review_path`, `design_review_report_path` and `design_summary_path`.

- A design set has a profile per unit kind ([ADR-0053](../../../docs/decisions/0053-design-template-profiles-by-unit-kind.md)): `<set>/<kind>/profile.md` (its version, files added or removed, instructions), templates that replace the set's as whole files, and `_examples/` for the designer. `appliesTo` and the `When` column are gone (the reader and `design_lib.py` report them). A document names `<set>@<n>` or `<set>/<kind>@<n>` and is stale per template. The reader (`designFilesFor(loaded, kind)`, `designTemplateOf`, `designBaseFiles`, `parseDesignProfile`) and `design_lib.py` (`files_for`, `template_of`, `parse_profile`) stay equal through the shared fixtures (`sets/detail/{api,screen,batch}`, `bad-sets/omega`, `resolved`); `scaffold_design.py` writes from the kind's template and its manifest names the profile, template file, reference and example; `check_design.py` reports `ref` per file; `paths.py` gains `design_profile_path`.

- An application with several legacy repositories is read whole ([ADR-0052](../../../docs/decisions/0052-several-legacy-repositories-per-application.md)): the runtime mounts each repository in `src/<repository id>/`, files are cited `<repository id>/<path>`, and provenance is `sources` (`<repository id>@<commit>` per repository; the `{sources}` placeholder and `--sources` of `inventory.py`, `finish_items.py`, `split_rules.py` and `render_rules.py` replace `{repo}`, `{commit}`, `--source-repo`, `--source-commit`, `--commit` and `--repo`). The inventory, the catalog index, the understanding record and the plan record `sources` (`catalogSources` in the plan), a unit card lists its `source` per repository, and `reconcile_catalog.py` reads a card's paths under their repository. `catalog_common.Owners` resolves a citation that drops the repository or keeps `src/`. The prompts of `assess`, the topology job, `extract-rules`, `harden-scan`, the designer and the member commands say that the source is several repositories; `scaffold.js` takes `sourceDirs`. `paths.py` gains `parse_sources`, `sources_spec`, `split_source_path` and `is_source_folder`.

- The document repository has the numbered layout of [ADR-0051](../../../docs/decisions/0051-document-repo-layout-legacy-and-modern.md): `paths.py` (the same in every plugin) builds `10-applications/<app>/01-legacy/` (the assessment with `_catalog/`, `_tools/`, `_analysis/`, `assessment.md`, `architecture.mmd`, `plan.md`, and per unit `spec.md`, `understanding.md`, the rules, findings, topology and trace) and `10-applications/<app>/02-modern/` (`requirements.md`, `_design/<set>/`, and per unit the card `README.md`, one folder per design set and `task.md`), `_generated/`, `01-standards/templates/<set>/` and `02-architecture/`. The scripts, commands, agents, workflows and the reader follow it; no old path is read. `finish_items.py --existing` is the modern half; scripts that walk unit folders skip the `_` folders.

- Design sets can be scoped to the application and carry their own instructions ([ADR-0050](../../../docs/decisions/0050-design-sets-scope-and-instructions.md)). `set.md` gains `scope: unit | application`, `reads` and a `## Instructions` section; the reader (`hooks/reader/design.ts`) and `design_lib.py` parse and validate them identically (shared fixtures `app-sets/`, `bad-app-sets/`, `appCases`); `scaffold_design.py` and `check_design.py` take `@app` for a set of the application, the manifest names the scope and the reads, and `check_design.py --report` always writes the multi-unit form (a single-unit run now gets its fix pass); the `designer` agent and the `design` command describe the application case; `paths.py` gains the application design paths.

- The basic and the detail design are generated by a runtime stage ([ADR-0049](../../../docs/decisions/0049-design-sets-generated-by-the-runtime.md)). New runtime plugin `design` (requires `reverse_engineering`) with the command `design` (flow: `scaffold_design`, a `designer` job per unit, `check_design`, a fix pass, `check_design`), the runtime agent `designer` (2.0.0) and the design-set scripts and fixtures moved from `modernize`; `scaffold_design.py` takes several units, `--out` and `--manifest`, `check_design.py` several units, `--tolerate` and `--report`; `paths.py` gains the design run paths. `modernize` no longer has the command `design` and the agent `designer`, and requires `design`.

- `codemode` joins the kernel tools ([ADR-0047](../../../docs/decisions/0047-kernel-extensions-codemode-and-http-mcp.md)), so every built-in agent (none lists its tools) can read many files in one script that prints only what it needs. An agent may name an MCP server in `tools` (`mcp__<server>__*`); the built-in agents name none.

- The `modernize` plugin follows the design lifecycle (ADR-0044, ADR-0045). Commands `design-architecture` (the common design: requirements, `02-architecture/blueprint.md`, the common components `02-architecture/common/COM-…`, the application's `to-be/design.md`, with two gates), `scaffold` (the target skeletons, the `scaffold` workflow and the `scaffolder`), `design` (one design set of one unit from the project's template, with the new `designer` agent) and `implement` (a unit's code and unit tests from its detail design) replace `brief`, `reimagine` and `transform`; `preflight`, `uplift` and the other strategies are removed with their agents (`uplift-migrator`, `version-delta-analyst`), workflows, `uplift_checks.py`. New scripts `design_lib.py`, `scaffold_design.py`, `check_design.py` and `validate_design_templates.py`, and a copy of `docmd.py`; `paths.py` gains the design paths. The reader `hooks/reader/design.ts` parses design sets and checks a design against its template; both are held to the shared fixtures in `modernize/scripts/tests/fixtures/design/`.

- The document repository holds Markdown only (ADR-0042). New `scripts/docmd.py` (front matter, tables, cards; the writer of every committed document) and `hooks/reader/document.ts` (its reader); `inventory.py` writes `inventory.md` and the per-file `inventory.json` into the run's scratch; new `render_topology.py` checks the extraction script's topology and writes `topology.md`; new `render_catalog.py` writes `catalog/index.md` and a card per item per module (with the links between items, computed from the topology), and the other catalog scripts read the committed catalog; `scope_items.py`, `split_rules.py`, `split_findings.py`, `finish_items.py`, `check_plan.py` and `rebuild_aggregates.py` write `understanding/{topology,rules,data-objects,findings,trace,understanding}.md`, `understanding/plan.md` and the Markdown read models; `plan_graph.py` reads the catalog instead of the topology. Removed the scripts of the earlier map/units flow (`units_from_topology`, `merge_traceability`, `write_work_items`, `merge_topology`, `node_packets`, `make_shards`) and the `JobOutput` JSON topology schema check (now a `topology.md` document check). The `reader` parsers read Markdown (`parseInventory`, `parseTopology`, `parseItemCatalog` over an index and its module documents, `parseUnitTrace`, `parseTraceSummary`, `buildTraceability`, `parseLedger`, `parsePlan`, `ruleCatalog`).

- The built-in agents list no `tools`: an agent file without `tools` runs with every kernel tool (runtime) or everything its harness offers (member), and `tools: []` still means none. `AgentManifest.tools` is optional and `toAgentDefinition` takes the kernel tool names to fill in the full set.

- Rename the `understand` plugin folder and name to `reverse_engineering`, the title the portal shows; `modernize` `requires` it under the new name. Stage and command ids (`assess`, `understand`, `plan-understand`) are unchanged.
- Drop `allowed-tools` from the skills (`mermaid-diagrams` in both plugins, `understand-planning`): a skill does not restrict the tools of the agent that loads it.

- Add the `plan-understand` stage to the `reverse_engineering` plugin (ADR-0041): `commands/modernize-plan-understand.md`, the agent `understand-planner` and the skill `understand-planning` (with `references/item-graph.md`), the scripts `plan_graph.py` (the item graph from the catalog and the topology) and `check_plan.py` (checks the planner's batches against the graph and measures them), with Python tests; `paths.py` gains the graph, draft and plan paths (copied into `modernize`).

- Adapt the upstream modernization method to Kintsugi runtime jobs, member harnesses, document-repository artifacts, and portal-owned progress presentation.
- Retain pure progress readers under `hooks/reader/`, mapping assessment, source and target data to Kintsugi repository namespaces for future portal use.
- Add the server-side JobOutput hook and its fail-closed credential scan, artifact-shape checks, redacted JSON report, bounds, and tests.
- Remove the Claude Code plugin manifest and pane/plugin-host code, including hook registration, terminal views, telemetry, and host-specific tests.
- `workflows/extract-rules.js` plans within the orchestrator's agent cap (`budget.agents`) instead of a fixed 1000, so its tail phases are never refused mid-run.
- Add the Kintsugi `understand` stage (`commands/modernize-understand.md`, no upstream counterpart) and its scripts `units_from_topology.py`, `merge_traceability.py` and `write_work_items.py`, with Python tests.
- The `assess` stage builds the item catalog (ADR-0033): `inventory.py` records a per-file sha256; new scripts `catalog_from_topology.py`, `apply_catalog_edits.py` and `reconcile_catalog.py` (shared helpers in `catalog_common.py`), with Python tests; the reader `parseItemCatalog` reads `assessment/<app>/catalog.json`.
- The `understand` stage runs on a selection of catalog items (ADR-0033): new scripts `scope_items.py`, `split_rules.py`, `split_findings.py` and `finish_items.py` (per-item topology fragments, rules, findings, traces, `meta.json` and work items, item-namespaced `RULE-<module>.<item>-NN` / `SEC-<module>.<item>-NN` ids), with Python tests; `workflows/harden-scan.js` takes `args.files`; the id patterns of `merge_traceability.py`, the JobOutput hook and the rule and finding readers accept the item-namespaced ids; `render_rules.render_rule` takes a given id; `commands/modernize-understand.md` is rewritten.
- Add `scripts/rebuild_aggregates.py` (ADR-0033): rebuilds an application's whole-application views under `assessment/<app>/generated/` and `knowledge/as-is/<app>/generated/` from its per-item files, with Python tests.
- Add the shared `mermaid-diagrams` skill (`skills/mermaid-diagrams/`, adapted from softaworks/agent-toolkit at `3027f20f3181758385a1bb8c022d4041dfb4de84`, MIT, see `NOTICE`): Mermaid only, a diagram type per artifact, syntax-safety rules for untrusted names and size limits, with condensed references for flowchart, sequence, er, c4 and state diagrams. `legacy-analyst`, `business-rules-extractor` and `architecture-critic` load it; the `assess`, `map`, `understand`, `brief` and `reimagine` commands name it in `metadata.skills`; `reverse-design` asks for sequence and ER diagrams.
- Replace the `mermaid-diagrams` skill with the WH-2099/mermaid-skill skill as published (commit `982d903`, MIT; ADR-0036): its `SKILL.md` and 37 `references/` files, `LICENSE` instead of `LICENSE-softaworks`; the Kintsugi artifact table, syntax-safety rules and size limits leave the skill. `scripts/mermaid_lint.py` and the JobOutput hook are unchanged.
- Runtime agents write with pi's `write` and `edit` instead of `outputs_write` (ADR-0037): the agent files list `tools: [read, ls, grep, find, write, edit]`, and the commands, workflows and prompts say `write`.
- Add `scripts/mermaid_lint.py`, a standard-library Mermaid lint (header, blocks, ids and keywords, quoted labels, classes, erDiagram cardinalities, C4 references, size limits; optional `mmdc` render), with Python tests. The JobOutput hook runs it over `.mmd` and Markdown outputs and reports what it finds as non-blocking `warnings`.
- Make the harden scan a stated manual review: `workflows/harden-scan.js` hands the assessment and the map to the finders as optional leads, every finding carries a confidence (latent weaknesses are Low-confidence findings, refuters lower their severity instead of refuting them), finders return the files they reviewed and the scanners that would apply and did not run (`toolsNotRun`, tool and reason), and a carry-over job settles every security highlight of the assessment (matched, added as a finding, or refuted with the reason). `SECURITY_FINDINGS.md` gains a **Review coverage** line, a confidence column, the **Assessment carry-over** table and the **Audit tools not run** table.
- `hooks/reader/findings.ts` reads each finding's confidence, the review coverage line, the carry-over table (`carryOverItems`: highlight, verdict, linked finding, reason; carry-over rows are never counted as findings) and the tools not run (`toolsNotRunItems`); older documents parse as before.
- Preserve upstream provenance: anthropics/claude-plugins-official `plugins/code-modernization` at `c8874f5ad883e26428f483ffa4d537cc81489e64`; see `NOTICE` and `LICENSE`.
- Runtime agents also get `shell` and `git`, and `ls` gains `tree`/`depth` (ADR-0040): the agent files list `tools: [read, ls, grep, find, write, edit, shell, git]`; `shell` runs one `bash -c` per call under the launcher's process rules, `git` takes explicit arguments (read-only subcommands anywhere in the workspace; mutating ones under `out`/`tmp` only), and the prompts describe the boundary instead of promising "no shell".
