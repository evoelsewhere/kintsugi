Coding Agent Workflow · CLI + MCP

The CLI connects. MCP gives context. The developer’s AI does the work.

The CLI installs and authenticates a local bridge. The chosen AI reads authorized Kintsugi context, works in the code repository with its own tools, and opens a pull request. Kintsugi observes provider state and reports workflow progress without taking over the coding session.

What the split means: MCP is the AI’s read-only question-and-context channel. kintsugi task watch is a separate CLI-to-Kintsugi SSE connection. Watch prints events; the developer decides when the chosen AI should refresh context. Kintsugi never injects prompts or launches coding work.
