# AI metrics

These metrics show whether AI adoption actually pays off on a migration project. Kintsugi computes them in the Monitoring pillar (C3).

## Definitions and suggested targets

| Metric | Definition | Suggested starting target |
|---|---|---|
| **AI coverage** | Share of project members who applied AI in their work during the period | 100 % |
| **AI active rate** | How often members use AI in project activities (active days / working days) | > 80 % |
| **SDLC coverage** | Share of pipeline activities (stages) in which AI was involved | > 70 % |
| **Feature time saved** | Time saved per feature vs. the baseline estimate | > 30 % |
| **Cost reduction ratio** | Cost saved through AI adoption vs. the baseline | > 15 % |
| **AI outcome ratio** | Deliverables fully or partly generated by AI ÷ all required deliverables | > 30 % |
| **Defect rate of AI output** | Defects per AI-generated deliverable, compared with human-produced ones | Below the human rate |

Targets are starting points; each project sets its own baseline in P0 (gate G0).

## Data sources

| Metric | Primary source | Supplementary source |
|---|---|---|
| Coverage, active rate | `HarnessActivity` from the Kintsugi MCP server / CLI | Harness telemetry (OTel, vendor metrics APIs) |
| SDLC coverage | Stage runs with `Provenance.origin` ∈ {`human-with-ai`, `runtime-agent`} | — |
| Time saved, cost reduction | Work item estimates vs. actuals (tracker), runtime cost (`UsageRecord`) | — |
| Outcome ratio | Artifact registrations with `aiShare` | `Assisted-by` commit trailers |
| Defect rate | Defects linked to artifacts through traceability, split by provenance | — |

The sources themselves are listed in [harness integration → telemetry](../reference/harness-integration.md#telemetry-sources). Collection is explained in [observability and telemetry](../architecture/concepts/observability-and-telemetry.md).
